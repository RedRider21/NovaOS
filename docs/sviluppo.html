1 · La struttura del repository

NovaOS vive in un unico repository con tre livelli ben separati:

NovaOS/
├─ shell/                     # web shell: l'intero "sistema" visibile (HTML/CSS/JS)
│  ├─ index.html              # boot · lockscreen · home · app · shade · navbar
│  ├─ css/style.css           # design flat, tema chiaro/scuro
│  ├─ js/os.js                # core: boot, blocco/PIN, window manager, notifiche, storage
│  ├─ js/apps.js              # app di sistema
│  ├─ sw.js · manifest.webmanifest · icon.svg
├─ android-launcher/          # contenitore Android (WebView) + ponte NovaNative
│  ├─ app/src/main/java/os/nova/launcher/   # MainActivity, CallHub, MailBridge, InCallService
│  ├─ build-apk.sh            # build manuale dell'APK senza Gradle
│  └─ setup-emulator.sh       # SDK + emulatore + AVD "nova"
├─ system/                    # livello ROM (AOSP / GSI): priv-app, whitelist, script
│  └─ make-emulator-rom.sh    # emulatore → dispositivo NovaOS senza ricompilare AOSP
├─ docs/                      # sito Pages (index/manuale/sviluppo) + guide (ROM, Mail, GeckoView)
└─ themes/                    # catalogo del negozio temi (catalog.json)

Il README del repository resta la fonte di verità e si aggiorna a ogni rilascio.

2 · Avviare la shell in un browser

Il modo più veloce per lavorare sull'interfaccia:

cd shell
python3 -m http.server 8091
# apri http://127.0.0.1:8091/index.html

In questa modalità telefonia, sensori e posta vera sono simulati (è il comportamento di default della shell quando non trova il ponte nativo), così puoi provare ogni app senza un telefono.

3 · Sull'emulatore Android

./android-launcher/setup-emulator.sh                  # una tantum: SDK + AVD "nova"

export ANDROID_HOME=$HOME/Android/Sdk
export PATH=$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$PATH
emulator -avd nova -no-window -no-audio -gpu swiftshader_indirect &

# servi la shell e aprilala nella WebView/Chrome dell'emulatore
cd shell && python3 -m http.server 8091 &
adb shell am start -a android.intent.action.VIEW -d "http://10.0.2.2:8091/index.html" \
  -n com.android.chrome/com.google.android.apps.chrome.Main

# screenshot: adb exec-out screencap -p > screen.png

4 · Trasformare l'emulatore in una ROM

Per avviare direttamente in NovaOS come interfaccia di sistema, senza ricompilare AOSP:

emulator -avd nova -writable-system -no-snapshot -gpu host
./system/make-emulator-rom.sh

Lo script installa NovaOS come priv-app, pusha la whitelist dei permessi privilegiati, disattiva launcher e setup di serie e imposta Home e telefono predefinito. Per tornare indietro: ./android-launcher/reset-device.sh oppure ricrea l'AVD. La guida completa (emulatore → GSI su device reale → AOSP) è nella Guida alla ROM.

5 · Compilare l'APK

La build è volutamente senza Gradle e senza IDE (servono solo openjdk-17 e l'Android SDK con build-tools 34):

bash android-launcher/build-apk.sh    # → android-launcher/build/novaos.apk

Lo script copia da solo la shell negli assets (passo [0]), così un clone pulito compila senza passaggi manuali; rigenera anche shell/version.json e shell/js/version.js dai numeri del manifest. L'APK include le librerie JavaMail per la posta reale.

La migrazione del motore a GeckoView cambierà questo percorso: GeckoView si distribuisce come AAR su Maven e richiede Gradle. Il piano è descritto in MIGRAZIONE-GECKOVIEW.md.

6 · Validazione rapida

La shell si verifica in modo automatico con Chrome headless, senza emulatore:

# verifica del DOM: la shell scrive un RESULT nel titolo
google-chrome --headless=new --disable-gpu --allow-file-access-from-files \
  --dump-dom --virtual-time-budget=10000 "file://…/shot.html?to=settings&report=1" \
  | grep -o '<title>[^<]*</title>'

In questo modo si controlla che ogni vista (home, telefono, impostazioni, launcher…) si apra senza errori prima ancora di compilare l'APK. Lo stato e le validazioni via emulatore sono documentati nel README.

7 · Pubblicare versioni e OTA

  1. Aggiorna i numeri nel manifest (android-launcher/app/src/main/AndroidManifest.xml: versionCode e versionName) e il banner shell/sw.js (CACHE).
  2. Compila: bash android-launcher/build-apk.sh rigenera versione e APK.
  3. Rilascia su GitHub: gh release create vX.Y …/novaos.apk. L'APK è il bootstrap; la shell si aggiorna da sola leggendo shell/version.json su main.

Il controllo avviene all'avvio: se version.json è più recente dell'installato, l'interfaccia propone l'aggiornamento da Impostazioni → Sistema.

8 · Temi .novatheme e catalogo

Un tema (.novatheme/2) può portare launcher, colori, forma e stile delle icone, sfondo e tipografia. La shell li importa da Impostazioni → Display → Importa tema oppure da URL/catalogo; il catalogo del negozio vive in themes/catalog.json. Le icone vettoriali dei temi sono applicate come immagini, mai come codice: importare un tema non è pericoloso.

9 · Contribuire

  • Segnalazioni: apri un issue sul repository GitHub indicando versione (da Impostazioni → Info sul telefono) e come riprodurre.
  • Modifiche: PR sul ramo main. Regole semplici: la shell deve restare avviabile in un browser (fallback simulati), il README si aggiorna a ogni rilascio e le pagine pubbliche (README, sito, release) restano in italiano.
  • Aree di lavoro aperte: la roadmap nel README — ROM su hardware reale via GSI, migrazione GeckoView (piano già scritto), poi la ROM definitiva.
